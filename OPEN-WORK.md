# Open work — wire-studio-kh

Open tasks and known defects for this repository only; updated in the same commit whenever work starts, changes, or closes. Shipped work lives in `CHANGELOG.md` and `docs/receipts/`.

- [ ] **The What's New sheet still shows 0.5.0's notes** — the sheet reads a hand-written list in `ui/app.js`, not the changelog, so a person opening the app after an update sees stale notes under the new version number. **Next:** generate the list from `CHANGELOG.md` at build time (the studio's own generator exists) and fail the build when the newest changelog heading and the version disagree.
- [ ] **Windowed idle footprint was never measured** — the gate records `UNMEASURED` because no running windowed instance is handed to it; the headless core measures 13 MB RSS. **Next:** set `IDLE_PID` in the next gate config against a hidden windowed instance and quote the measured figure on that receipt.
- [ ] **Packaged SIGTERM acceptance is not closed** — the probe stops because launching the packaged app trips the window/foreground safety check. **Next:** run it against a hidden launch with its own data dir and record the exit code and absence of a window.
- [ ] **The Settings → Gateway card has never been clicked in a window** — the command behind the button is proven live against a real Gateway (21 asserts), but the in-app click is unproven. **Next:** click it once in a hidden instance with its own data dir and record what the card says.
- [ ] **A published Wire asset must carry the content-hash prefix** — 0.5.3 shipped as `Wire.Studio.KH_0.5.3_aarch64.dmg` because `gh release create` was called directly and the wrapper that adds the prefix never ran; 0.5.4 shipped correctly as `62b663a667fd-Wire.Studio.KH_0.5.4_aarch64.dmg`. The wrapper is the updater repo's `packaging/github-asset.sh`, not this repo's. **Next:** keep uploading through that wrapper, and run the release-asset name check for this repo and tag before publishing.
- [ ] **Push `main` before cutting the release tag** — v0.5.3 was tagged from remote HEAD before `main` was pushed, so that tag names 0.5.2's commit. **Next:** the next release pushes `main` first, then creates the tag and the release.
- [ ] **Wire's own update has never been watched installing** — Sparkle is built and wired: `scripts/build-release.sh` writes `SUPublicEDKey` from this app's key file and asserts `SUFeedURL` (`:57`, `:114`), the framework ships in the bundle, and the appcast is served and signed (`docs/appcast.xml`, `scripts/appcast.sh`). What is unproven is the swap on an installed older build. **Next:** on a Mac holding 0.5.3, let it take 0.5.4 and record the version readback before and after.
